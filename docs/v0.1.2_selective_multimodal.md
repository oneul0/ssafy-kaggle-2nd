# v0.1.2 선택적 멀티모달 학습 전략

## 1. 실험 목적

v0.1.2는 기존 v0.1의 전체 모델 구조와 학습 파이프라인을 유지하면서, **이미지 modality에 대한 과도한 의존을 완화했을 때 일반화 성능이 향상되는지 검증**하는 실험 버전이다.

핵심 아이디어는 다음과 같다.

- 모든 샘플에서 이미지가 동일한 중요도를 가지는 것은 아니다.
- 이미지가 항상 완전한 형태로 제공되면 모델이 시각적 shortcut에 과적합할 수 있다.
- 학습 중 이미지 정보를 부분적으로 제한하면 질문/텍스트 정보와 이미지 정보를 더 균형 있게 활용할 가능성이 있다.
- 구조 자체를 크게 변경하지 않고 regularization 관점에서 가설을 검증한다.

---

## 2. 핵심 가설

### 가설

> 학습 과정에서 일부 이미지 정보를 제거하거나 약하게 변형하면 모델의 이미지 shortcut 의존성이 감소하고, 질문과 이미지 정보를 더 균형 있게 활용하여 validation 일반화 성능이 향상될 것이다.

### 근거

Aeneas 논문은 이미지가 존재한다고 해서 모든 task에 동일하게 사용하지 않았다.

- geographical attribution에는 이미지 정보를 사용했다.
- restoration에서는 leakage 가능성 때문에 이미지 정보를 제외했다.
- chronological attribution에서는 이미지 추가가 유의미한 성능 향상을 보이지 않아 사용하지 않았다.

즉, **multimodal input은 무조건 많이 사용하는 것이 아니라 실제 task에 기여하는 modality를 선택적으로 활용해야 한다**는 전략이다.

또한 데이터 규모가 제한된 환경에서 과적합을 줄이기 위해 다음과 같은 augmentation 및 regularization을 적용했다.

- text masking
- text clipping
- word deletion
- punctuation dropping
- image zoom / rotation
- brightness / contrast augmentation
- dropout
- label smoothing

v0.1.2에서는 이 아이디어를 현재 문제에 맞게 단순화해 적용한다.

| 항목 | v0.1 | v0.1.2 |
|---|---|---|
| 기본 모델 | 기존 모델 | 유지 |
| 데이터 split | 기존 split | 유지 |
| 질문/정답 처리 | 기존 방식 | 유지 |
| 이미지 입력 | 항상 정상 이미지 | 일부 확률로 image dropout |

이를 통해 성능 변화가 발생했을 때 원인을 보다 명확하게 해석할 수 있도록 한다.

## 4. 실험 전략

### 4.1 Image Modality Dropout

학습 과정에서 일정 확률로 정상 이미지를 제거하거나 neutral image로 대체한다.

초기 권장값:

```text
p = 0.10 ~ 0.15
```

예:

```python
if random.random() < image_dropout_prob:
    image = neutral_image
```

목적:

- 이미지 feature만을 이용한 shortcut 방지
- 질문/text representation 활용 증가
- 특정 시각 패턴에 대한 과적합 완화

처음부터 dropout 확률을 크게 설정하지 않는다.

권장 탐색:

```text
0.00  → baseline
0.10  → 1차 실험
0.15  → 필요 시 추가
0.20+ → 0.1.2 단계에서는 우선 제외
```

---

### 4.2 Weak Image Augmentation

원본 이미지의 의미를 훼손하지 않는 범위에서만 augmentation을 적용한다.

우선 적용 후보:

- resize
- 작은 범위의 crop
- 약한 brightness 변화
- 약한 contrast 변화

주의할 augmentation:

- 강한 random crop
- 큰 회전
- 좌우 반전
- 객체나 정답 단서를 가릴 수 있는 augmentation

VQA 계열 문제에서는 augmentation이 정답 근거 자체를 제거할 수 있으므로 v0.1.2에서는 **강한 augmentation보다 안정적인 perturbation을 우선**한다.

## 6. 반드시 검증해야 할 부분

### 6.1 구현 정상 여부

실험 전에 다음을 확인한다.

- image dropout이 training에서만 동작하는가
- validation/test에서는 원본 이미지를 그대로 사용하는가
- dropout된 이미지가 processor 입력 규격에 맞는가
- augmentation 이후 이미지 shape/range가 정상인가
- augmentation이 질문 또는 정답 데이터에 영향을 주지 않는가
- random seed를 고정했는가
- v0.1과 동일한 train/validation split을 사용했는가
- optimizer, scheduler, epoch, batch size 등 다른 조건이 동일한가

핵심은 **v0.1 → v0.1.2에서 바뀐 변수를 최소화하는 것**이다.

---

### 6.2 Image Dropout 실제 적용률

설정한 확률과 실제 적용 비율이 일치하는지 기록한다.

예:

```text
Configured dropout probability: 0.10
Observed dropout ratio: 0.098
```

batch 단위가 아니라 sample 단위로 실제 적용 횟수를 확인하는 것이 좋다.

---

### 6.3 정상 이미지 / 이미지 제거 성능 비교

validation 단계에서 동일한 모델을 다음 입력으로 평가한다.

#### Full

```text
Question + Original Image
```

실제 leaderboard와 가장 가까운 평가.

#### D-only 또는 Text-biased Control

```text
Question + Neutral/Masked Image
```

이미지가 없을 때 모델이 어느 정도까지 답할 수 있는지 확인한다.

#### Image-heavy Control

가능하다면 질문 정보를 최소화하거나 별도의 분석 subset을 이용하여 이미지 의존성을 확인한다.

핵심 비교:

```text
Full Score
vs
Masked Image Score
```

두 점수 차이가 지나치게 크다면 모델이 이미지에 매우 강하게 의존하고 있을 가능성이 있다.

---

### 6.4 Shuffle Test

validation 이미지의 순서를 무작위로 섞어 질문과 잘못된 이미지를 연결한다.

```text
정상:
Q1 - I1
Q2 - I2
Q3 - I3

Shuffle:
Q1 - I3
Q2 - I1
Q3 - I2
```

해석:

- 점수가 크게 하락하면 실제 이미지 정보를 적극적으로 사용하는 것
- 점수가 거의 유지되면 이미지 활용도가 낮거나 질문 bias가 강할 가능성
- v0.1.2가 v0.1보다 shuffle에서 덜 취약하면서 Full 성능이 유지되면 보다 안정적인 representation을 학습했을 가능성

단, shuffle score 자체가 높다고 좋은 것은 아니다.  
**Full 성능을 유지하면서 shortcut 의존성이 줄어드는지**를 함께 봐야 한다.

---

### 6.5 질문 유형별 성능

가능하면 질문을 유형별로 나눈다.

예:

```text
색상
개수
위치
객체 식별
행동
관계
텍스트/OCR
상식성 질문
```

각 유형별로 v0.1과 v0.1.2의 성능 변화를 비교한다.

특히 확인할 것:

- 이미지 의존도가 높은 질문에서 성능이 과도하게 하락하지 않는가
- 질문 bias가 강한 유형에서 validation 성능이 좋아지는가
- 특정 질문 유형에서만 전체 score 개선이 발생한 것은 아닌가

전체 평균만 보면 중요한 실패 패턴이 가려질 수 있다.

## 8. 결과 해석 기준

### Case 1. Train 성능 ↓ / Validation 성능 ↑

```text
Train Score       ↓
Validation Score  ↑
Train-Val Gap     ↓
```

가설을 가장 강하게 지지하는 결과다.

해석:

- 기존 모델이 일부 시각 feature에 과적합했을 가능성
- image dropout/augmentation이 regularization 역할 수행
- 보다 일반화 가능한 multimodal representation 형성

판단:

```text
v0.1.2 채택 후보
```

---

### Case 2. Train 성능 ≈ / Validation 성능 ↑

매우 좋은 결과다.

해석:

- 학습 능력을 거의 희생하지 않으면서 일반화 성능 개선
- perturbation 강도가 적절할 가능성

판단:

```text
v0.1.2 채택 가능성이 높음
```

---

### Case 3. Train 성능 ↓ / Validation 성능 ↓

해석 후보:

1. image dropout 확률이 너무 높음
2. augmentation이 정답 정보를 훼손함
3. 현재 task가 예상보다 이미지 의존도가 높음
4. 모델 capacity가 충분하지 않아 입력 perturbation을 견디지 못함

다음 실험:

```text
dropout 0.15 → 0.05~0.10
augmentation 강도 축소
Image Dropout only 실험
Augmentation only 실험
```

---

### Case 4. Train 성능 ↑ / Validation 성능 ↓

과적합 가능성이 높다.

특히 augmentation을 추가했는데 이런 결과가 나온다면 구현이나 split 문제를 먼저 확인한다.

검증:

- augmentation이 validation에도 적용되고 있지 않은가
- train/validation preprocessing이 달라졌는가
- seed/split이 기존 실험과 동일한가

---

### Case 5. Full Score는 동일하지만 Mask/Shuffle 성능 변화

이 경우 전체 점수만으로 판단하지 않는다.

예:

```text
v0.1
Full    0.70
Mask    0.40
Shuffle 0.42

v0.1.2
Full    0.70
Mask    0.46
Shuffle 0.39
```

가능한 해석:

- 최종 성능은 같지만 modality 사용 방식이 변함
- 질문 정보 활용 능력이 증가했을 가능성
- 잘못된 이미지에 대한 민감도가 커졌다면 실제 이미지-grounding이 개선됐을 수도 있음

따라서 auxiliary evaluation을 함께 봐야 한다.

---

### Case 6. Image-heavy 질문만 크게 하락

예:

```text
색상/개수/위치 질문 ↓
상식/언어 질문 ↑
전체 score 소폭 ↑
```

이 경우 전체 score 개선만 보고 바로 채택하지 않는다.

실제 test set에 image-heavy 질문 비중이 높다면 leaderboard 성능이 악화될 수 있다.

다음 단계에서는 질문 유형에 따라 dropout probability를 다르게 적용하는 **conditional modality dropout**을 고려할 수 있다.

## 12. 최종 요약

### 전략

기존 v0.1 구조를 유지하면서 **Image Modality Dropout + Weak Image Augmentation**을 적용한다.

### 가설

이미지에 대한 과도한 shortcut 학습을 줄이면 질문과 이미지 정보를 보다 균형 있게 사용하는 representation을 학습할 수 있고 validation 일반화 성능이 향상될 것이다.

### 핵심 검증

```text
1. v0.1 대비 Validation Score
2. Train-Val Gap
3. Full / Mask / Shuffle 비교
4. 질문 유형별 성능
5. seed 반복 안정성
```

### 결과 판단

단순히 validation score 하나만 비교하지 않고,

> **성능 + modality 의존성 + 일반화 gap + 질문 유형별 변화**

를 함께 보고 v0.1.2의 가설을 판단한다.
