# VQA 전략 문서

## Version 0.0 → Version 0.1

### 가설 1. 정답 토큰에만 Loss를 적용하면 성능이 향상될 것이다.

**근거**

Version 0.0은 `Prompt + Question + Choices + Answer` 전체에 Loss를 적용한다.

하지만 실제 평가 대상은 최종 정답 `a/b/c/d` 하나뿐이다. 따라서 질문과 프롬프트를 다시 생성하는 데 학습 자원을 사용하는 것은 직접적인 평가 목표와 일치하지 않는다.

Version 0.1에서는 정답 토큰에만 Loss를 적용해 LoRA의 제한된 학습 용량을 **정답 선택 능력에 집중**시킨다.

**변경**

```text
Full Sequence Loss
→ Answer-only Loss
```

---

### 가설 2. 이미지 해상도를 높이면 Text-VQA 문제의 정확도가 향상될 것이다.

**근거**

학습 데이터를 분석했을 때 가게 이름, 가격, 전화번호, 표지판, 문구 등 **이미지 속 작은 텍스트를 읽어야 하는 질문 비중이 높았다.**

Version 0.0의 384 수준 고정 해상도에서는 작은 글자가 축소 과정에서 손실될 가능성이 있다.

따라서 Qwen2.5-VL의 동적 이미지 처리를 활용해 더 많은 visual token을 유지하면 OCR 성격이 강한 문제에서 유리할 것으로 예상한다.

**변경**

```text
384 Fixed Resolution
→ Higher / Dynamic Resolution
```

---

### 가설 3. 생성 방식보다 Choice Logit Scoring이 더 안정적일 것이다.

**근거**

대회의 출력 공간은 자유로운 문장이 아니라 정확히 네 개이다.

```text
a / b / c / d
```

Version 0.0에서는 문장을 생성한 뒤 `a/b/c/d`를 다시 parsing한다. 이 과정에서는 `"정답은 c입니다"`, `"C"`, `"(c)"`처럼 출력 형식이 달라질 수 있다.

반면 네 선택지의 logit을 직접 비교하면 parsing 과정이 필요 없으며, 모델이 각 선택지를 얼마나 선호하는지도 score 형태로 얻을 수 있다.

**변경**

```text
generate()
→ text parsing
→ answer

에서

a/b/c/d logits
→ argmax
```

---

### 가설 4. 전체 Train 데이터를 사용하면 generalization 성능이 향상될 것이다.

**근거**

Version 0.0의 약 200개 학습은 코드와 학습 pipeline의 정상 동작을 확인하기 위한 설정에 가깝다.

실제 Train 데이터는 6,714개이므로 200개만 사용할 경우 다양한 이미지, 질문 유형, 표현 방식을 충분히 학습하기 어렵다.

따라서 코드 검증 이후에는 전체 Train 데이터를 사용하는 것이 합리적이다.

**변경**

```text
약 200 samples
→ 전체 6,714 samples
```

---

### 가설 5. Train 내부 Validation을 분리하면 전략 선택의 신뢰도가 높아질 것이다.

**근거**

해상도, epoch, learning rate 등의 설정을 Test 또는 Leaderboard 결과에 의존해 조정하면 Test 분포에 과적합될 위험이 있다.

또한 Train 데이터에는 동일하거나 유사한 질문 표현이 반복되므로 단순 random split은 validation 성능을 과대평가할 가능성이 있다.

따라서 Train 내부에서 validation을 분리하고, 가능하면 동일 질문이 양쪽에 섞이지 않도록 group-aware split을 사용한다.

**변경**

```text
학습 → Test 제출

에서

Train
├─ Training
└─ Validation
     ↓
모델 및 하이퍼파라미터 결정
```

---

## Version 0.0 → 0.1 요약

| 항목          | Version 0.0   | Version 0.1              |
| ----------- | ------------- | ------------------------ |
| Base Model  | Qwen2.5-VL-3B | 동일                       |
| Fine-tuning | QLoRA         | 동일                       |
| Loss        | 전체 Sequence   | **Answer-only**          |
| Resolution  | 384 수준 고정     | **Higher / Dynamic**     |
| Inference   | Generation    | **Choice Logit Scoring** |
| Answer 처리   | Parsing       | **Argmax**               |
| Train Data  | 약 200개        | **전체 6,714개**            |
| Validation  | 제한적           | **Train 내부 Validation**  |

### 핵심 가설

> **모델 자체를 변경하지 않고도 학습 목표, 이미지 정보량, 추론 방식, 데이터 활용 방식을 객관식 VQA 문제에 맞게 정렬하면 Version 0.0보다 높은 Accuracy를 얻을 수 있다.**
